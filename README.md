# PDF 필기 제거

PDF에서 손글씨·펜 자국만 지우고 인쇄된 내용은 그대로 남기는 도구입니다.

필기가 어떻게 들어갔느냐에 따라 처리 방식이 완전히 다릅니다.

| | 앱에서 필기한 PDF | 스캔한 종이 문서 |
|---|---|---|
| 예 | 아이패드 마크업, 굿노트, PDF Expert, Adobe | 종이에 펜으로 쓰고 스캔·촬영 |
| 필기 저장 형태 | PDF 주석(annotation) 객체 | 그냥 픽셀 |
| 처리 | 해당 객체만 삭제 — **추측 없음** | 픽셀 분석 휴리스틱 |
| 결과 | 원본 화질 그대로, **글자 선택·검색 유지**, 파일 크기 유지 | 페이지가 이미지로 바뀜 |

앱에서 필기한 PDF는 구조가 남아 있으므로 정확히 지울 수 있습니다. 프로그램이 자동으로 판별해 가능한 쪽을 택합니다.

구현은 두 가지가 있습니다.

| | `web/` (정적 PWA) | `app/` (서버) |
|---|---|---|
| 용도 | GitHub Pages 등 정적 호스팅, **아이폰/아이패드에서 홈 화면에 추가**해 앱처럼 사용 | 직접 호스팅하는 웹 서버 |
| 처리 위치 | 브라우저 안 (서버 없음, 파일이 외부로 전송되지 않음) | 서버 (Python + OpenCV) |
| 성능 | 수백 페이지 문서를 병렬 처리 | 순차 처리 |
| 상태 | **주 구현.** 개선 작업은 여기에 이뤄집니다 | 초기 구현, 유지만 |

---

## `web/` - 정적 PWA (주 구현)

빌드 과정이 없습니다. `web/` 폴더를 그대로 정적 호스팅에 올리면 되고, PDF 렌더링(pdf.js)·필기 감지/제거(직접 구현한 순수 JS)·PDF 출력(jsPDF)이 전부 브라우저 안에서 실행됩니다.

### 성능

120페이지 A4 문서(150dpi, 데스크톱 Chromium, 워커 3개) 실측:

| 항목 | 값 |
|---|---|
| 전체 소요 시간 | **31.7초** (페이지당 262ms) |
| JS 힙 사용량 | **121MB** (페이지 수에 비례해 크게 늘지 않음) |
| 감지·제거 연산만 | 페이지당 104ms (2.2MP 기준, 단일 스레드) |

페이지당 262ms 중 감지·제거는 워커에서 병렬로 처리되고, 남는 시간은 메인 스레드의 PDF 렌더링과 JPEG 인코딩입니다. 모바일에서는 대체로 2~3배 느리므로 100페이지 기준 1~2분을 예상하면 됩니다.

도형을 지키기 위한 획 굵기 분석(거리 변환)을 넣으면서 24.6초 → 31.7초로 29% 느려졌습니다. 인쇄된 도형·차트를 지워 버리는 것보다는 이 편이 낫다고 판단했습니다. 앱에서 필기한 PDF는 이 경로를 아예 타지 않으므로 몇백 페이지도 1초 안에 끝납니다.

속도를 만든 설계는 다음과 같습니다.

- **페이지를 한 장씩 처리하고 즉시 해제** — 렌더링된 캔버스를 쌓아두지 않고, 처리가 끝나는 즉시 JPEG으로 인코딩해 메모리에서 놓습니다. 수백 페이지를 동시에 들고 있으면 iOS Safari가 탭을 종료시킵니다.
- **워커 병렬 처리** — 기기 코어 수에 맞춰 워커를 띄우고(모바일 2개, 데스크톱 4개 상한), 페이지 픽셀 버퍼를 복사 없이 transfer로 주고받습니다. UI는 멈추지 않습니다.
- **스크래치 버퍼 재사용** — 페이지당 ~25MB의 작업 버퍼를 워커마다 한 번만 할당하고 모든 페이지에서 재사용합니다.
- **알고리즘** — 연결 요소 라벨링 1회, 분리 가능(separable) 팽창으로 O(n·r²)→O(n), 인페인팅은 마스크 경계에서 안쪽으로 번지는 BFS로 O(마스크 픽셀). 필기가 없는 페이지는 감지 직후 조기 종료합니다.

### 앱에서 필기한 PDF (주석 제거)

PDF를 열어 필기 계열 주석 객체(`Ink`, `Highlight`, `Underline`, `FreeText`, 도형 등)를 찾아 삭제하고 다시 저장합니다. 페이지 내용 스트림은 건드리지 않으므로 글자·이미지·레이아웃이 원본 그대로입니다. 문서 자체의 링크(`Link`)와 양식 필드(`Widget`)는 필기가 아니므로 보존합니다.

실측(주석 6개가 있는 3페이지 문서): 펜 색상 픽셀 14,329 → **0**, 텍스트 1,179자 **그대로 유지**, 파일 18KB. 같은 문서를 이미지 처리로 돌리면 약 1.8MB에 글자는 검색할 수 없게 됩니다.

> 앱에서 "내보내기" 하며 필기를 페이지에 병합(flatten)한 파일은 주석이 남지 않으므로 아래의 이미지 처리로 넘어갑니다.

### 스캔한 문서 (픽셀 분석)

구조가 없으므로 잉크 덩어리(연결 요소)를 하나씩 떼어 내어 판정합니다.

- **extent** = 면적 / 바운딩박스 면적. 인쇄 글자는 자기 상자를 꽤 채우지만(측정값 0.34 이상), 펜 자국은 넓게 휘저으며 조금만 채웁니다(0.08~0.21).
- **circularity** = 4π·면적 / 둘레². 인쇄 글자는 뭉툭하고, 필기는 길고 구불구불합니다.
- **획 굵기 편차(CV)** — 거리 변환의 능선에서 획 굵기를 재고 그 변동 계수를 봅니다. **이게 도형·그래프를 지키는 핵심입니다.** 원, 화살표, 표 상자, 차트 선은 필기만큼이나 성글고 구불구불해서 위의 두 지표로는 구분되지 않지만, 기계가 그린 선은 굵기가 일정합니다(실측 최대 0.23) 반면 펜은 필압에 따라 변합니다(중앙값 0.49).
- **색상 비율** — 인쇄 글자와 다른 색 펜은 강한 신호입니다. 단 픽셀이 아니라 *덩어리* 단위로 판정하고(픽셀 단위면 검정 글자 주변 JPEG 색번짐에 걸림), 컬러로 인쇄된 제목이 지워지지 않도록 모양 조건도 함께 봅니다.
- **직선 런렝스** — 표 테두리나 밑줄은 축에 정렬된 긴 직선 한 줄입니다. 손으로 그은 선은 미세하게 흔들려 짧은 런으로 쪼개집니다. 이 검사가 없으면 표 전체가 필기로 오인됩니다.

임계값은 렌더링한 테스트 문서에서 실측해 정했습니다. 현재 `webtests/fixtures/`의 문서 기준으로 인쇄 텍스트·컬러 제목·표·도형/차트 성분은 **하나도 지워지지 않습니다**.

**정밀도를 재현율보다 우선**했습니다. 인쇄물을 잘못 지우는 것이 필기를 남기는 것보다 나쁘기 때문에, 애매한 경우는 남기는 쪽으로 판단합니다.

그 대가는 실측으로 이렇습니다. 축소·압축된 테스트 문서에서 컬러 펜 자국은 9,337px → **0**으로 완전히 지워지지만, 검정 펜 자국은 7,798px → 2,946px으로 일부가 남습니다. 남는 것은 축소·압축 과정에서 굵기 변화가 뭉개져 기계로 그린 선과 구분되지 않게 된 획입니다.

원본 이미지에서 이미 정보가 사라진 경우이므로 **렌더 해상도를 올려도 회복되지 않습니다**(200dpi로 다시 처리해도 2,935px으로 동일). 검정 필기가 많이 남는 문서라면 `web/js/handwriting.js`의 `strokeCvThreshold`(기본 0.28)를 낮추면 감지율이 올라가지만, 그만큼 인쇄된 도형이 지워질 위험이 커집니다. 컬러 펜은 이 한계와 무관하게 안정적으로 지워집니다.

### GitHub Pages로 배포하기

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다 (최초 1회, 웹에서 직접 해야 합니다).
2. 기본 브랜치에 push하면 `.github/workflows/deploy-pages.yml`이 `web/` 폴더를 자동 배포합니다. Actions 탭에서 진행 상황과 배포된 URL을 확인할 수 있습니다.

### 아이폰/아이패드에서 앱처럼 쓰기

1. Safari로 배포된 주소에 접속합니다.
2. 공유 버튼 → **홈 화면에 추가**를 누르면 아이콘이 생기고 주소창 없이 앱처럼 실행됩니다.
3. PDF는 파일 앱이나 사진 앨범에서 선택할 수 있습니다.

### 로컬에서 미리 보기

```bash
cd web && python3 -m http.server 8000
```

### 테스트

```bash
npm install
npm test
```

### 한계

- 필기 감지는 규칙 기반 휴리스틱입니다. 인쇄 글자와 겹친 필기, 인쇄체에 가까운 또박또박한 글씨는 남을 수 있고, 반대로 손으로 자를 대고 그은 밑줄은 표선으로 판단해 남길 수 있습니다.
- 지운 자리는 주변 배경색으로 메웁니다. 배경에 무늬가 있으면 자국이 보일 수 있습니다.
- 완성된 PDF는 다운로드 전까지 메모리에 있어야 합니다. 150dpi 기준 페이지당 약 0.6MB이므로, 200페이지가 넘으면 앱이 해상도를 "빠르게"로 낮출 것을 안내합니다.
- Safari 16.4 미만처럼 모듈 워커를 지원하지 않는 브라우저에서는 메인 스레드 단일 처리로 자동 전환됩니다. 동작하지만 느리고 처리 중 화면이 덜 부드럽습니다.

## `app/` - 서버 버전 (Python/FastAPI)

OpenCV 기반의 초기 구현입니다. 감지 방식이 다릅니다(획 굵기 편차 + solidity). `web/` 쪽이 더 정확하고 빠릅니다.

```bash
sudo apt-get install -y tesseract-ocr   # 선택: 시스템 의존성 없음
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
pytest
```

## 프로젝트 구조

```
web/                     정적 PWA (주 구현)
  index.html
  manifest.webmanifest   PWA 매니페스트 (홈 화면 추가용)
  service-worker.js      앱 셸 오프라인 캐시
  css/style.css
  js/
    app.js               UI + 페이지 파이프라인 (레인 단위 병렬 처리)
    annotations.js       앱 필기(PDF 주석) 탐지·삭제 (pdf-lib)
    pool.js              워커 풀 (+ 메인 스레드 폴백)
    worker.js            페이지 처리 워커
    pdfRender.js         PDF → 캔버스 (pdf.js)
    handwriting.js       필기 감지/제거 분류기
    imageProc.js         픽셀 처리 프리미티브
    pdfExport.js         캔버스 → JPEG → PDF (jsPDF)
  icons/
webtests/
  annotations.test.mjs   주석 제거 테스트
  handwriting.test.mjs   분류기 정확도 테스트
  fixtures/              측정용 렌더링 문서 + 주석 PDF

app/                     서버 버전 (Python/FastAPI)
tests/                   서버 버전 테스트

.github/workflows/
  deploy-pages.yml       web/ 를 GitHub Pages에 자동 배포
```
