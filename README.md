# PDF 필기 제거

스캔한 PDF에서 손글씨·펜 자국만 지우고 인쇄된 내용은 그대로 남기는 도구입니다. 두 가지 구현이 있습니다.

| | `web/` (정적 PWA) | `app/` (서버) |
|---|---|---|
| 용도 | GitHub Pages 등 정적 호스팅, **아이폰/아이패드에서 홈 화면에 추가**해 앱처럼 사용 | 직접 호스팅하는 웹 서버 |
| 처리 위치 | 브라우저 안 (서버 없음, 파일이 외부로 전송되지 않음) | 서버 (Python + OpenCV) |
| 성능 | 수백 페이지 문서를 병렬 처리 | 순차 처리 |
| 상태 | **주 구현.** 개선 작업은 여기에 이뤄집니다 | 초기 구현, 유지만 |

---

## `web/` - 정적 PWA (주 구현)

빌드 과정이 없습니다. `web/` 폴더를 그대로 정적 호스팅에 올리면 되고, PDF 렌더링(pdf.js)·필기 감지/제거(직접 구현한 순수 JS)·PDF 출력(jsPDF)이 전부 브라우저 안에서 실행됩니다.

### 성능

120페이지 A4 문서(150dpi, 데스크톱 Chromium, 워커 3개) 실측:

| 항목 | 값 |
|---|---|
| 전체 소요 시간 | **24.6초** (페이지당 205ms) |
| JS 힙 사용량 | **95MB** (페이지 수에 비례해 크게 늘지 않음) |
| 감지·제거 연산만 | 페이지당 88ms (2.2MP 기준, 단일 스레드) |

페이지당 205ms 중 감지·제거는 워커에서 병렬로 처리되고, 남는 시간은 메인 스레드의 PDF 렌더링과 JPEG 인코딩입니다. 모바일에서는 대체로 2~3배 느리므로 100페이지 기준 약 1분 안팎을 예상하면 됩니다.

속도를 만든 설계는 다음과 같습니다.

- **페이지를 한 장씩 처리하고 즉시 해제** — 렌더링된 캔버스를 쌓아두지 않고, 처리가 끝나는 즉시 JPEG으로 인코딩해 메모리에서 놓습니다. 수백 페이지를 동시에 들고 있으면 iOS Safari가 탭을 종료시킵니다.
- **워커 병렬 처리** — 기기 코어 수에 맞춰 워커를 띄우고(모바일 2개, 데스크톱 4개 상한), 페이지 픽셀 버퍼를 복사 없이 transfer로 주고받습니다. UI는 멈추지 않습니다.
- **스크래치 버퍼 재사용** — 페이지당 ~25MB의 작업 버퍼를 워커마다 한 번만 할당하고 모든 페이지에서 재사용합니다.
- **알고리즘** — 연결 요소 라벨링 1회, 분리 가능(separable) 팽창으로 O(n·r²)→O(n), 인페인팅은 마스크 경계에서 안쪽으로 번지는 BFS로 O(마스크 픽셀). 필기가 없는 페이지는 감지 직후 조기 종료합니다.

### 필기 감지 방식

잉크 덩어리(연결 요소)를 하나씩 분석해 모양으로 판정합니다.

- **extent** = 면적 / 바운딩박스 면적. 인쇄 글자는 자기 상자를 꽤 채우지만(측정값 0.34 이상), 펜 자국은 넓게 휘저으며 조금만 채웁니다(0.08~0.21).
- **circularity** = 4π·면적 / 둘레². 인쇄 글자는 뭉툭하고, 필기는 길고 구불구불합니다.
- **색상 비율** — 인쇄 글자와 다른 색 펜은 모양과 무관하게 필기입니다. 단, 픽셀 단위가 아니라 *덩어리* 단위로 판정합니다(픽셀 단위로 보면 검정 글자 주변 JPEG 색번짐에 걸립니다).
- **직선 런렝스** — 표 테두리나 밑줄은 축에 정렬된 긴 직선 한 줄로 이뤄집니다. 손으로 그은 선은 미세하게 흔들려 짧은 런으로 쪼개집니다. 이 검사를 먼저 하지 않으면 표 전체가 필기로 오인됩니다.

임계값은 렌더링한 테스트 문서에서 실측해 정했습니다(`webtests/fixtures/mixed_document.png`, 인쇄 텍스트 55개 + 컬러 제목 12개 + 표 30개 + 필기 5개 성분 전부 정확히 분류).

### GitHub Pages로 배포하기

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다 (최초 1회, 웹에서 직접 해야 합니다).
2. 기본 브랜치에 push하면 `.github/workflows/deploy-pages.yml`이 `web/` 폴더를 자동 배포합니다. Actions 탭에서 진행 상황과 배포된 URL을 확인할 수 있습니다.

### 아이폰/아이패드에서 앱처럼 쓰기

1. Safari로 배포된 주소에 접속합니다.
2. 공유 버튼 → **홈 화면에 추가**를 누르면 아이콘이 생기고 주소창 없이 앱처럼 실행됩니다.
3. PDF는 파일 앱이나 사진 앨범에서 선택할 수 있습니다.

### 로컬에서 미리 보기

```bash
cd web && python3 -m http.server 8000
```

### 테스트

```bash
npm install
npm test
```

### 한계

- 필기 감지는 규칙 기반 휴리스틱입니다. 인쇄 글자와 겹친 필기, 인쇄체에 가까운 또박또박한 글씨는 남을 수 있고, 반대로 손으로 자를 대고 그은 밑줄은 표선으로 판단해 남길 수 있습니다.
- 지운 자리는 주변 배경색으로 메웁니다. 배경에 무늬가 있으면 자국이 보일 수 있습니다.
- 완성된 PDF는 다운로드 전까지 메모리에 있어야 합니다. 150dpi 기준 페이지당 약 0.6MB이므로, 200페이지가 넘으면 앱이 해상도를 "빠르게"로 낮출 것을 안내합니다.
- Safari 16.4 미만처럼 모듈 워커를 지원하지 않는 브라우저에서는 메인 스레드 단일 처리로 자동 전환됩니다. 동작하지만 느리고 처리 중 화면이 덜 부드럽습니다.

## `app/` - 서버 버전 (Python/FastAPI)

OpenCV 기반의 초기 구현입니다. 감지 방식이 다릅니다(획 굵기 편차 + solidity). `web/` 쪽이 더 정확하고 빠릅니다.

```bash
sudo apt-get install -y tesseract-ocr   # 선택: 시스템 의존성 없음
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
pytest
```

    worker.js            페이지 처리 워커
    pdfRender.js         PDF → 캔버스 (pdf.js)
    handwriting.js       필기 감지/제거 분류기

  icons/
